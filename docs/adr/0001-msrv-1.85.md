# ADR 0001: Raise MSRV from 1.78 to 1.85

- Status: Accepted
- Date: 2026-08-05
- Deviates from: `MULTISCAN-SDD-v1.0.md` front-matter (`MSRV 1.78`) and the CLAUDE.md workflow note (`MSRV 1.78`).

## Context

The spec pins MSRV 1.78. Empirically, the dependency versions the project
requires no longer support it. Verified by building `cargo +1.78 build
--workspace --exclude xtask` and `cargo +1.82 ...`:

- **`clap_lex 1.1.0`** (pulled transitively by `clap 4`) declares
  `edition = "2024"` in its own manifest, which cargo can only parse on
  **Rust 1.85+** (edition 2024 stabilized in 1.85). On 1.78 and 1.82 the build
  fails at manifest-parse time: `feature edition2024 is required`.
- **`ed25519-dalek 2.2.0`** (T-306, air-gap bundle signing) declares
  `rust-version = "1.81"`.

`cargo +1.85 build --workspace --exclude xtask` finishes cleanly, so 1.85 is
the true floor for the current dependency set.

Two dependencies chosen for security reasons contribute to the modern baseline
and are worth keeping rather than downgrading:

- **`ed25519-dalek`** — signing for air-gap bundles (FD-005). No maintained
  older line avoids the ecosystem's 1.81+ move.
- **`cap-std`** — structural confinement of OCI layer extraction (SCA-005,
  NFR-010); `openat2`/`RESOLVE_BENEATH` makes write-through-symlink escape
  impossible rather than relying on hand-rolled `lstat` checks. This is the
  single highest-risk surface in the product, so a capability-confined FS is
  worth a modern toolchain.

## Decision

Raise the workspace MSRV to **1.85** (edition 2021 is retained for our own
crates; the bump is purely the compiler floor). Update:

- `Cargo.toml` `[workspace.package] rust-version = "1.85"`
- `clippy.toml` files `msrv = "1.85"`
- the CI `msrv` job toolchain to `1.85`

The spec's `MSRV 1.78` is superseded by this ADR (per CLAUDE.md: "Spec and code
disagreeing means the code is wrong, unless an ADR in `docs/adr/` says
otherwise").

## Consequences

- 1.85 (released 2025-02) is widely available; the static musl / cross-compile
  targets (NFR-007/008) are unaffected — they are about target triples, not
  compiler version.
- Code written to avoid 1.82+ APIs (`Option::is_none_or`, `iter::repeat_n`) may
  now use them, but existing avoidances are left in place; no churn is
  warranted.
- If holding a lower MSRV becomes a hard requirement, the path is pinning
  `clap_lex` below 1.1.0 and `ed25519-dalek` below the 1.81 line (and swapping
  `cap-std` for a hand-rolled confined extractor) — a deliberate, larger change
  that this ADR consciously declines.
